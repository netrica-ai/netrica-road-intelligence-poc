The intelligence layer on the LiDAR you already own.

Netrica reads a mobile-LiDAR survey of a road corridor and returns what a 2D map cannot: the usable carriageway width at every station, the vertical clearance and the object that binds it (wire, shop shade, tree canopy, structure), junctions, IRC / CMVR standards flags, and a per-vehicle passability verdict that gates routing. This page is the working prototype: three Indian cities, measured end to end, served as a static application you are running right now.

One scan, several deliverablesWhat the engine extracts from a mobile-LiDAR survey

↔

Clear carriageway width

Read from the road points themselves at every station, not from lane markings. Encroachments narrow the reading. Validated at 0.10 m mean absolute error against hand-traced boundaries.

↕

Vertical clearance + binding object

Lowest object over the drivable band, split into wire / structure (permanent) and vegetation (prunable), with the named object class that binds (wire, shop shade, advertisement board, tree canopy).

◈

Asset & utility classes

12-class semantic segmentation (poles & towers, wires, wire–structure connectors, boards, fencing, road-side objects, vehicles, vegetation, buildings, ground, road), trained on a 62-category Indian taxonomy.

✕

Junctions

A training-free detector reads intersections as topological defects in the road's orientation field; T/Y, 4-way, skew and rotary types. 215 hand-labelled junctions: completeness 0.80, correctness 0.85.

§

Standards flags

Width classes W0–W4 (IRC:86 lane classes), clearance classes H0–H3 (CMVR 3.8 m cap, IRC 5.0 m road clearance), fused accessibility classes A0–A3.

🚑

Vehicle passability & routing

Per-vehicle verdicts (ambulance 3.0 / 3.5 m, fire truck 3.5 / 4.5 m, aerial appliance 3.5 / 5.0 m) transferred to the OSM road graph; accessibility-gated Dijkstra / A* routing runs client-side in milliseconds.

Live · corridor auditEvery number, traceable to the points it came from

The audit viewer walks one survey path at a time through the measurement chain: ① carriageway boundary → centreline → junctions → width at every station, ② overhead clearance per stream (wire / structure / vegetation) with the fitted wire spans and the critical stations, ③ the fused per-vehicle verdict. Hand-digitised ground truth (boundary polygons, junction labels) can be overlaid on the validation paths, and the Deployment panel reruns the same chain on model-predicted labels instead of hand labels, which is how the pipeline behaves on a new corridor.

Deployment readinessFrom a Rodic survey to a decision layer

The pipeline needs no new field work. Input is the LiDAR a survey has already produced; output is a set of standard GIS layers and this web application, deployable on the road owner's own infrastructure.

1 · IngestLAS/LAZ + trajectory (any MLS platform: handheld, vehicle, dual-scanner). Tiling, ground filter, corridor extraction.
2 · SegmentPoint Transformer V3 foundation encoder (Sonata / Concerto / Utonia), merged across cities so the model travels and the data stays.
3 · MeasureBoundary → centreline → junctions → width per station; wire / structure / vegetation clearance; binding object; multi-drive fusion.
4 · CertifyIRC / CMVR tiers (W, H, A), per-vehicle passability code, transfer to the OSM graph, accessibility-gated routing.
5 · DeliverGeoJSON / GeoPackage layers, 3D Tiles, this static web app (no server), PDF audit, REST endpoint on request.

Runs where the data is

  • On-premise or cloud. Batch pipeline in Python / PyTorch on one NVIDIA A100 / L40S-class GPU; geometry steps are CPU-only. The delivery layer is static files served by any web server or object store.
  • Data sovereignty by design. Cross-city deployment is done by model merging: fine-tuned encoders are combined in weight space, so raw scans never leave the owner. Consistent with the Geospatial Data Guidelines 2021.
  • No personal data in the product. LiDAR-only outputs are geometry and class. Any imagery used in development is face- and number-plate-blurred before it is shown; person points carry no colour.
  • Human in the loop. Every flag carries the measured evidence and a class; a compliance verdict is signed off by an engineer in the audit viewer before it leaves.
  • Integration. Outputs load directly into QGIS / ArcGIS / PostGIS and Rodic's monitoring dashboards; segment ids map to any asset schema via a mapping table.

Per-station record (as served on this page)

{
  "type": "Feature",
  "geometry": { "type": "LineString", "coordinates": [...] },   // EPSG:32643, 5–10 m station
  "properties": {
    "path": "Bhopal_1",       // survey drive / path id
    "wm": 6.99,               // measured clear width, m
    "w": 4,                   // width class W0–W4 (5 = WU, one-sided)
    "hm": 3.94,               // binding vertical clearance, m (null = open sky)
    "h": 2,                   // clearance class H0–H3
    "a": 2,                   // accessibility class A0–A3 (4 = AU)
    "bind": "Wire",           // binding object class (62-category taxonomy)
    "bstream": "wire"         // wire | structure | vegetation
  }
}

Plus: junction points with type and radius, the fused multi-drive width graph, and the routing graph with a 3-bit block code per edge (width / wire-structure / vegetation) per vehicle class.

What is live, what is next, what we do not claim

  • Live on this page: segmentation, width, clearance, binding object, junctions, standards classes, per-vehicle passability, network transfer and routing on Bhopal, Kerala and Chandigarh; validation against hand-digitised ground truth.
  • Next (PoC window on a Rodic corridor): run the chain on a Rodic-supplied LAS/LAZ sample (Mumbai twin or an OPRMC stretch), map our 12/62-class taxonomy to Rodic's asset schema, and export the per-object asset register (class, position, height, offset) as a GeoPackage alongside the station layers shown here.
  • Not claimed: road gradient / slope (not a pipeline step today); survey-free operation from street-view imagery (a pilot: road is recovered well, thin wires are not, so it signals re-survey rather than certifies); any result on data we have not processed.
